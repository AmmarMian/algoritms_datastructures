Exercice 1 - Tris

On s'intéresse dans cet exercice à la notion de tri d'un tableau d'entiers. Supposons que l'on a un tableau tab d'un nombre d'éléments connus, on veut écrire une procédure qui modifie le tableau pour le trier à l'aide du tri à bulle dont le principe est le suivant

  1. On parcourt le tableau de gauche à droite en comparant les éléments deux à deux.
  2. Si deux éléments consécutifs ne sont pas dans l'ordre, on les échange.
  3. On recommence jusqu'à ce que le tableau soit trié.

Exercice 2 - Un compteur

On donne le programme suivant qui incrémente la valeur d'un compteur:

void procedure(int n) {
  int compteur = 0;
  int i = 0;
  int j;
  while (i < n) {
    j = i + 1;
    while (j <= n) {
      compteur++;
      j++;
    }
    i+2;
}

On veut estimer la complexité en temps de cette procédure en fonction de la taille de l'entrée \(n\) dans le cas particulier où \(n\) est une puissance de 2. Pour cela répondre aux questions suivantes :

  1. Quelle est la valeur finale du compteur dans le cas où \(n=16\) ?
  2. Puisque \(n\) est une puissance de 2, on peut écrire \(n=2^p\) ave \(p\) un entier positif connu. Exprimer alors la valeur finale du compteur en fonction \(p\).
    On pourra essayer de compter le nombre fois que l'on incrémente la variable compteur et utiliser un résultat sur la somme des puissances de \(2\).
  3. Exprimer le résutlat précédent en fonction de \(n\).
  4. En déduire la complexité de cette procédure

Exercice 3 - Recherche dichotomique

On s'intéresse à la recherche dichotomique dans un tableau trié. Le principe est le suivant:

  1. On considère un tableau trié \(tab\) de taille \(n\) et un élément \(x\) à chercher.
  2. On compare \(x\) à l'élément du milieu du tableau.
  3. Si \(x\) est plus petit, on cherche \(x\) dans la première moitié du tableau, sinon on le cherche dans la deuxième moitié.
  4. On répète le processus jusqu'à trouver \(x\) ou bien jusqu'à ce que la taille du tableau soit nulle.
  5. Si on ne trouve pas \(x\), on renvoie \(-1\).

  2. Supposons que l'élément que l'on cherche se trouve dans le tableau. Quel scénario correpsond au pire cas ?
  3. Combien de divisions du tableau doit-on effectuer dans ce cas ?
  4. En déduire la complexité en temps de cet algorithme. Est-ce plus efficace qu'une recherche linéaire classique ?
  5. Quelle est la complexité en espace de cet algorithme ?
